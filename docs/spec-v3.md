## 1. プロジェクト概要

- **タイトル**: tayori -たより-
- **サブタイトル**: 行き先を決めずにことばを放つ場所。
- **目的**: 承認や比較のプレッシャーがないまま、自分の内面のことばを記録し、放つ。そして誰かのことばと偶然出会う。静かな空間を提供する。
- **技術構成**: Flask + SQLite / Render / Resend （※ v3起草時の記載は Flask + PostgreSQL (Neon) + pgvector。§6 参照）

## 2. コアコンセプトと設計原則

### 2.1 守るべき「しない」原則（運用ではなく構造で担保）

- **承認をつくらない**: いいね数、保存数、閲覧数、ランキング、トレンド等の数字は一切算出せず、DBにも持たず、表示しない。
- **比較をつくらない**: 他者のアクションや人気度が可視化される要素を排除する。
- **返事をつくらない**: コメント、リプライ等のSNS的な相互作用を設けない。
- **義務をつくらない**: ログインボーナス、デイリー通知など、ユーザーを追い立てる仕組みを入れない。

### 2.2 AIの立ち位置（本プロダクトの背骨）

> **AIはあなたの言葉を読みます。ただし、評価はしません。**

v2までの「AIは本文を絶対に読まない」原則は撤回する。代わりに、**読んだ結果を何にも使わない**ことを構造で担保する。AIは評価者ではなく、翻訳者・裏方として機能する。

**構造での担保（実装要件）**

| 項目 | 要件 |
|---|---|
| 保存 | embeddingは本文とは別テーブル（`letter_vectors`）に格納。生成後、AIは本文を再参照しない |
| スコア | 検索時の類似度はリクエスト内でのみ使用し、**永続化しない**。DBにスコアカラムを作らない |
| 推薦 | 「あなたへのおすすめ」「人気の言葉」等のレコメンド機能を実装しない |
| 学習 | ユーザーの投稿を学習・分析・統計処理に使用しない |
| 開示 | 上記をプライバシーポリシーおよび `/about` に平易な日本語で明記する |

AIが行うのは以下の3つのみ。

1. **意味の翻訳**: 検索入力と言葉のベクトルマッチング
2. **外部テキストの抽出**: パブリックドメイン作品からの詩的なフレーズの切り出し
3. **安全性の担保**: ケアが必要な投稿の検知（門番 / §4.6）

### 2.3 二層構造：漂う と 探す

tayoriには2つの層がある。**デフォルトは常に「漂う」**。

| 層 | 手がかり | 距離の指標 | 起動 |
|---|---|---|---|
| **漂う** | 空気（色相・季節・時間帯・天気） | `air_distance()` | 常時。アプリを開いた初期状態 |
| **探す** | 意味・感情（ベクトル） | Semantic Gravity | ユーザーが能動的に呼び出したときのみ |

「言葉の引力」は、**呼ばないと来ない**。検索は主機能ではなく、能動的なユーザーだけが使う副機能として設計する。

## 3. 空間設計

### 3.1 宙（そら）の構造

- 画面全体が一つの「宙」。
- 球面上に格子状に配置された「部屋」が緩やかに自転する（正射影、傾き23.4°、ピッチ22°、90秒で一周）。
- 無限スクロールではなく、スワイプによる空間のパン（カメラ移動）とズームイン/アウトで探索する。

### 3.2 言葉の振る舞い

- 物理演算（衝突・反射）により空間を浮遊する。
- 古い言葉は約1年で沈降するが、約100日に一度「浮上（flare）」する。
- 近傍に配置されるかどうかは `air_distance()` で決まる。ユーザーの「今」（時刻・天気・季節）に近い条件で書かれた言葉ほど、手前に漂う。

## 4. 機能要件

### 4.1 放つ（投稿）

- **本文**: 最大80字。匿名。
- **題（title）**: 任意、10字以内。一覧表示でのみ使用し、宙を漂う本文には混ざらない。
- **気分の色**: 書く画面に常時表示される色相＋トーンのバー（HSL）。`air_distance()` の手がかりとなる。
- **打鍵の実時間再生（TypeTrace）**:
  - 入力過程（ためらいの間、消した文字）を記録し、宙で再生する。
  - 長すぎる間は対数圧縮（上限5秒）し、「にじみ」として表現。
- **自動保存される環境情報**: 季節 / 時間帯バンド / 天気
- **削除**: 放ってから48時間以内は取り消し可能。（※ 未実装。§8-C-1）

### 4.2 漂う（デフォルト体験）

- アプリ起動時、ユーザーは何もせずとも宙の中にいる。
- `air_distance()` により、ユーザーの現在の環境に近い言葉が近傍に配置される。
- 検索窓はこの状態では**表示されない**。
- 一日の閲覧可能量は個人ごとに制限し、毎日4:00 JSTにリセットする。

### 4.3 探す（Semantic Gravity）

- **呼び出し方**: 部屋の中に置かれた、罫だけの一行。（§8-A で確定）
- **UI**: 単一の静かなテキスト入力窓。単語（例「雨」）から文章（例「誰かに背中を押してほしい」）まで入力可能。
- **挙動**:
  - 入力内容をベクトル化し、コサイン類似度で近い言葉を抽出。
  - **リスト表示は行わない**。該当する言葉が宙の深層からユーザーの周囲へふわりと引き寄せられ、星座のように浮かび上がる。
  - 検索結果件数、該当数、ローディングバーは表示しない。
- **検索対象**: いま見ている部屋の中のユーザー投稿。（※ 外部テキストは未実装。部屋を越える経路は作らない）
- **禁止事項**: 検索クエリの履歴を永続化しない。類似度スコアを保存しない。

### 4.4 言葉の漂流物（外部テキスト）

**v1の対象はパブリックドメインのみ。**（※ 全体が未着手。§8-B）

| 種別 | 扱い | v1実装 |
|---|---|---|
| PD（青空文庫・著作権切れ） | 宙に漂う。ユーザー投稿と同じ空間に共存 | ✅ する |
| 現代のWebエッセイ | 本文を載せない。タイトル＋リンクのカード形式のみ可 | ❌ しない（住む場所がないため） |
| 現代の詩 | 書き手への直接許諾が前提。80字で全文になりうるため引用では通らない | ❌ しない（渡西後に人力で交渉） |

**取り込みパイプライン（PDのみ）**

- 青空文庫のXMLをパース（スクレイピング不要）。
- AIが情景や余白を持つ一節を80字以内で抽出。
- **表現の差異化**: ユーザー投稿のようなTypeTrace再生は行わず、「インクがじわっと染み出す」静かなフェードインで表示する。
- **出典表示**: タップして開いたときのみ、隅に小さく `— 夏目漱石『こころ』より` と刻印を表示する。
- **外部リンクは張らない**。tayoriから外に出ていく導線を作らない。

### 4.5 触れる・残す・届く

#### 灯（ともしび）

- 誰かが言葉を開いて読んでいる間、その言葉の周囲が7秒間ふわりと灯る。
- ユーザー投稿の場合、作者の画面上でも、自分の過去の言葉が読まれるとリアルタイムで7秒の灯がともる。
- **回数は数えない・表示しない**。

#### 棚

- 出会った言葉を最大10個の「棚」に保存できる（名前付き、移動可能）。
- **付箋**: 読み手が自分の棚の中でのみ使える私的な分類タグ。他者からは見えない。

#### 棚に残された報せ

- 自分の放った言葉が誰かの棚に保存された際、静かな通知を届ける。
- **1つの言葉につき、生涯1通のみ**（`shelved_notified` フラグで制御）。2人目以降の保存では何も起こらない。
- 文面例: 「あなたの言葉『（冒頭のフレーズ…）』は、誰かの手元にあります。」
- 保存された回数・人数は**絶対に**表示しない。書架（`/me?tab=archive`）の該当の言葉が温かく発光する。

#### 季節の返却

- 放った言葉は、季節が巡ったときに書き手本人のもとへ静かに返ってくる。
- 返却時、書いた当時の色・天気・時間帯とともに提示する。

### 4.6 門番（メンタルヘルス配慮）

- **段階的強化方針**: v1ではキーワード判定のみの軽い実装とし、ユーザー数の増加に応じて精度を上げていく。過剰な検知による誤ブロックを初期は避ける。
- **【初日から必須】** 書く画面の目立たない位置に、`/contact`（相談窓口）への小さな導線を**常設**する。判定の有無にかかわらず常に表示する。
- 検知した場合も、宙への投稿自体はブロックせず、投稿後に一度だけ静かに窓口を提示する方針を基本とする。

## 5. UI/UX ガイドライン

- **タイポグラフィの極値**: 画像等のノイズがないため、カーニング、行間、明度に徹底的にこだわる。
- **トランジション**: 言葉が現れる際、最初はわずかにぼやけ、フォーカスが合うと明瞭になる。
- **アニメーション**: Apple的なスプリング物理。呼吸のような揺れは周期4〜15秒、非対称波形。
- **ミニマリズム**: 検索結果件数、倍率表示、ローディングバー等、「システムを操作している」と感じさせる要素を極限まで削ぐ。

## 6. データモデル（実装の実態）

### 6.0 基盤：なぜ Postgres + pgvector ではないのか

v3 の起草時は Neon の PostgreSQL に pgvector を載せる前提で書かれていたが、**実装は SQLite 単一ファイル（`tayori.db`）**で動いている。意味の索引も pgvector ではない。

本番は Render の starter（512MB）。Transformer をそのまま載せると、実測で e5-small の int8 ONNX でも RSS 411MB——アプリの 50MB と合わせて載らなかった（メモリアリーナを切っても変わらない）。そこで **model2vec**（文の埋め込みモデルを「語→ベクトル」の静的な表へ蒸留したもの）へ切り替えた。推論は表を引いて平均するだけで、torch も onnxruntime も要らず、numpy だけで 0.07ms/件。

リポジトリに置いてあるのはこの二つだけ（`scripts/build_semantic_table.py` が手元で一度だけ生成する）。

| ファイル | 中身 | 大きさ |
|---|---|---|
| `semantic/potion_ja.npz` | 語ベクトル表（fp16・25,134語 × 256次元） | 約12MB |
| `semantic/tokenizer.json.gz` | 刈り込んだ分かち書き辞書 | 約0.3MB |

母数が数千のあいだは全件の内積で足りるので、ANN 索引も外部ベクタDBも要らない。**この構成を pgvector へ戻す判断をする場合、512MB の壁を先に解く必要がある。**

### 6.1 letters — 宙のことば本体

`mode='sky'` の行が宙にある。手紙時代からのテーブルを引き継いでいるため、名前が v3 の記述と一致しない列がある。

| 列 | 中身 | v3の記述との差 |
|---|---|---|
| `id` TEXT PK / `user_id` TEXT | | |
| `poem` TEXT | 本文（80字） | v3 は `body`。手紙時代の名前をそのまま使っている |
| `title` TEXT | 題（10字） | |
| `seal_color` TEXT | 気分の色。`hsl(199, 70%, 62%)` の**文字列一本** | v3 は `hue` / `saturation` / `lightness` の3列。分けていない |
| `seal_color_chosen` INTEGER | 選ばれた色か。0 の色は空気の計算から外す（既定色は発言ではない） | v3 に記載なし |
| `seal_env` TEXT | 放った時の天気の JSON（city / condition / temp / humidity / pressure / precip / temp_tag） | v3 は `weather` 単一列 |
| `time_bucket` TEXT / `weather_event` TEXT | 時刻帯・天気の補助。欠測があり、`_mood_hour()` / `_mood_weather()` が `sent_date` から補う | v3 は `time_band` |
| `sent_date` TEXT | 放った時刻。**季節はここから導く** | v3 は `season` 列を持つ想定。持っていない |
| `room_id` INTEGER | → `rooms.id` | v3 に記載なし（宙の骨格） |
| `trace_z` BLOB | 打鍵の記録（zlib圧縮）。旧 `trace` TEXT は 527fe64 で落とした | v3 に記載なし |
| `sky_status` TEXT | 門番の三値（`live` / `pending` / `blocked`。NULL は v13 以前＝live 扱い） | v3 に記載なし |
| `shelved_at` / `shelved_notified` / `shelved_notify_attempts` | 棚の報せ（生涯1通） | `shelved_notified` のみ v3 に記載あり |
| `returned_count` INTEGER | 季節の返却が起きた回数 | v3 に記載なし |
| `first_seen_season` / `first_seen_at` | 出会いの痕跡（`summer_night` の形の鍵だけ） | v3 に記載なし |
| `vertical` INTEGER | 縦書きか | |

**持っていない列**

- `area_name` — **一切保存していない**。2026-07-29 に地図を畳んだ時、位置を書き込む経路ごと無くなった。`air_distance()` からも地名の項（5%）を落とし、残る4成分へ比率を保って引き伸ばしてある（色 0.421 / 季節 0.211 / 時刻 0.211 / 天気 0.157）。§2.3・§3.2 から「エリア名」を落としたのはこのため。
- `deleted_at` — 無い。§4.1 の48時間の取り消しが未実装のため（§8-C-1）。
- `released_at` — 無い。`sent_date` が兼ねている。
- **スコア・保存数の列** — v3 の要求どおり、無い。

**手紙時代の残骸**: `photo` / `voice` / `emos` / `stamp` / `font` / `demo_mode` / `arrive_*` / `open_*` / `seal_q` など多数の列が残っている。宙のモデルの一部ではなく、読み書きもしていない（`demo_mode` だけは種のことばの除外に今も効く）。

### 6.2 letter_vectors — 意味の索引

v3 が `letter_embeddings` と呼んでいるもの。

```
letter_vectors
  letter_id TEXT PRIMARY KEY   ← letters.id
  model     TEXT               ← 'potion-multilingual-128M-ja'
  dim       INTEGER            ← 256
  v         BLOB               ← fp32 のベクトル
  made_at   TEXT
```

- **本文は持たない**（v3 の要求どおり）。
- `source_type` 列は無い。外部テキストがまだ無いため（§4.4 着手時に足す）。
- 現在 409 行（`letters` の宙のことばと同数）。
- ことばが消えると同じトランザクションで消える（`sem_forget` / `sem_forget_user`）。退会時は**ことばより先に**ベクトルを落とす（letters を消した後だとどれがその人のものか分からなくなるため）。

### 6.3 external_texts — 未作成

§4.4 が未着手のため、テーブルも取り込みスクリプトも存在しない。着手時に作る。

なお、いま宙にある300通の**「種のことば」は PD ではない**（`scripts/seed_room_words.py` で置いた、部屋を無人にしないためのことば）。`letters` に通常の行として入っており、作者は実在の人にしていない。外部テキストとは別のものとして扱う。

### 6.4 宙を運用するテーブル（v3 §6 に記載が無いが骨格）

| 表 | 役割 |
|---|---|
| `rooms` | 部屋。`position_index` が球面格子の席。`locked_at` は他人のことばが入った瞬間の施錠 |
| `sky_cursor` | 閲覧者×部屋のデッキ（`cycle_seed` / `position` / `dealt_day` / `dealt_ids`）。§8-A の「一日の閲覧量」の実体 |
| `sky_cycle_seen` | 一巡のあいだに配り終えたことば |
| `sky_seen` | きょう見たことば。48時間を超えた行は日次で手放す |
| `sky_deliveries` | 宙から一人へ届ける便り |
| `sky_marks` | 灯（印） |
| `sky_reaction` | 触れられた記録 |
| `muted` | 自分の宙から消したことば（書き手には何も伝わらない） |
| `shelves` / `shelf_items` / `saved_words` / `saved_tags` | 棚10・控え・付箋 |
| `users` / `drafts` / `unemptyable_trash` / `notes` ほか | 手紙時代からの併存 |

## 8. 決定済みの値と、まだ空いているもの

### 8-A. 決まったもの（実装に入っている）

v3 §8 で「未確定」としていた論点のうち、以下は実装の中で決着している。値はすべて環境変数で動かせる（既定値を記す）。

| 論点 | 決定 | 根拠 |
|---|---|---|
| embeddingモデルと次元 | `potion-multilingual-128M-ja`（model2vec 蒸留）/ **256次元**。本文は外部のAI事業者へ送らず、サーバ内で完結する | §6.0。e5-small の int8 ONNX でも RSS 411MB で 512MB に載らなかった |
| 類似度のしきい値 | コサイン **0.30** 未満は「近い」と呼ばない（`_SEM_HIT_MIN`） | 部屋『心』49通の実測。**在るもの**は「雨」0.85・「眠れない」0.90、**無いもの**は「母」0.08・「学校」0.07。0.30 はこの二つの山のあいだの谷で、「無いものは無い」と言えるようにするための線 |
| 引き寄せる上限数 | 探す専用の上限は置かない。宙の枠（`_SKY_N`=9）に、しきい値を越えたものだけが入り、**足りなくても埋めない** | cbcf32d。定員を埋めようとすると、遠いものに「最も近い」の顔が付く |
| 宙の表示密度 | 一度に漂わせる他者のことばは `_SKY_MAX`=40 まで（宙全体）。部屋の中の枠は `_SKY_N`=9、うち `_SKY_FRESH_K`=2 を新着レーンに充てる | |
| 意味の取り分 | **0.85**（`_AIR_SEM_SHARE`）。探すを自分から起こした時にだけ効き、既定の漂いでは 0 | 順位で均すのをやめた時に前提ごと置き直した。探すは利用者が自分から起こした行いで、そこへ「あなたのいまの天気」を半分ぶつけるのは頼まれていないことをしている。残す 0.15 は、同じくらい近いことばが並んだ時にどれが大きく浮かぶかを決めるぶん |

### 8-C. 本文（§1〜§5）と実装のズレ — 要判断

§6・§8 の改稿で分かった、**本文側を直すか実装を足すかの判断が要る**箇所。

1. **§4.1「放ってから48時間以内は取り消し可能」— 未実装。**
   ルートも UI も存在しない（DELETE メソッドのルートが一つも無く、`letters` の行を消すのは退会と、手紙時代の屑籠だけ）。`_room_lock_if_needed()` の注釈が「48時間の削除窓でそのことばが消えても鍵は外さない」と、**あるかのように書いている**のがまぎらわしい。実装するか、本文から落とすか。

2. **§4.3「検索対象はユーザー投稿＋外部テキストの両方」— 前者のみ、かつ部屋の中だけ。**
   部屋を越えて探す経路は意図的に作っていない（プライバシーポリシー第4項に明記済み）。本文を「いま見ている部屋の中」に直すのが実態に合う。

   宙全体では出ないので「呼ばないと来ない」の趣旨は守られているが、文言は実態と違う。§4.3 の呼び出し方は 8-A に合わせて書き換え済み。
