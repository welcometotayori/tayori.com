# tayori UI/UX レビュー ＆ リデザイン3案

作成日: 2026-07-21
対象: `templates/index.html`（投函・受信・年表）を中心とした本体UI
目的: **AIっぽさを隠す / 人の手感を出す / 利用者が安心して心を開ける空間にする**

---

## 総評

典型的なAIデザイン（紫グラデ・カード地獄・Inter・絵文字アイコン・stock写真）は**ほぼ無い**良好な状態。
土台（生成りの紙・墨・朱の抑えた配色、Shippori Mincho 明朝一本、封蝋・縦書き、紙のノイズテクスチャ）は世界観として完成度が高い。

**参考**: `ui-ux-pro-max` の design-system エンジンが tayori 用に自動提案してきたアクセント色は `#6366F1`（インディゴ＝いわゆる "AI紫"）。
tayori の既存の朱 `--seal #B5543A` はこの汎用デフォルトを正しく退けている。
→ 方向性は合っており、**虹グラデーションだけが汎用美学に引きずられて残っている**という構図。

---

## 案1｜気分カラー：虹スペクトル → 手染めの温度スウォッチ

**最小リスク・最大効果。まずこれから。**

### 現状の問題
投函画面の「いまの色」だけが全色相の虹グラデ（`templates/index.html:391` の `.color-band`）。
周囲の墨・生成り・朱の抑えた世界から浮き、"カラーピッカー" というソフトウェア部品に見える。
UX原則 `color-not-decorative-only` の観点でも、七色は「気分」ではなく「色選択UI」として読まれてしまう。

### 案
連続グラデをやめ、**手で混ぜたような低彩度の温度スウォッチ 5〜6枚**に。
軸は「沈んだ ⇄ あたたかい」。

| 例 | HEX | 色名の目安 |
|----|-----|-----------|
| 藍鼠 | `#5B6B73` | 沈んだ |
| 利休鼠 | `#8A8F86` | |
| 枯色 | `#C9B79C` | |
| 枇杷 | `#D8A96A` | |
| 洗朱 | `#C7724E` | |
| 朱（seal） | `#B5543A` | あたたかい |

- 各チップは正円でなく **わずかに歪んだ角丸** ＋ にじみ影で「絵の具の色見本」に。
- 選択は拡大でなく **チップが少し沈む**（`scale(.96)`）。

### 効果
連続値より「今日の気分に近いものを1つ選ぶ」という**行為の重み**が出て、AI感が消える。

### 実装メモ
CSSの `.color-band` の `linear-gradient` と JSの `MOOD_STOPS` は**対で更新**が必要（既知の地雷）。
`--seal` や地図ピン色はブランド色なので触らない。

## 案2｜手の痕跡を宿す：均一ピル → 活版・付箋の非対称

### 現状の問題
「1週間後／3ヶ月後 …」「写真を入れる／声を録る」「投函・受信・年表」が全部**同じ角丸ピル／等分セグメント**。
UX的には正しいが、コンポーネントライブラリ＝アプリの匂い。すべて中央対称なのも汎用レイアウトの筆頭。

### 案
- **期間チップ**: 角丸カプセル → 切手・付箋の浅い角（2–3px）。
  選択中は朱ベタ塗りでなく **インクの下線 ＋ 0.5°の傾き**（"手で丸をつけた" 印）。
- **投函／受信／年表**: 枠を外し **活字の見出し ＋ 現在位置に朱の下線**（`nav-state-active` は下線で担保）。
- **撮影／録音ボタン**: 横並びの二つ子ピルをやめ、便箋の **綴じ代（左）にアイコンだけ** を寄せて非対称に。

### 効果
「設定画面の部品」から「一枚の紙の上の書き込み」へ。触れる要素が手仕事に見え、心理的な硬さが取れる。

### 注意
純正フォント一本（Shippori Mincho）は**識別子として維持**する。
エンジンは手書きフォント（Kalam / Patrick Hand）を提案したが、それに替えると世界観が壊れるので**不採用が正解**。

## 案3｜書く行為を主役に：モードレスな一枚の便箋 ＋ 到着の物理演出

### 現状の問題
投函画面が「ヘッダー＋タブ＋便箋＋メタ設定（届く頃・時刻・色）＋封をする」と**ダッシュボード的に積層**。
書く前に運用UIが目に入り、"アプリを操作している" 感が先に立つ。
`primary-action`（1画面1主役）と `progressive-disclosure` の観点で改善余地。

### 案
書くときは**便箋だけが画面を占める**モードレス構成に。

- タブ・差出人・ロゴは書き始めるとスッと退く（`scroll` でなく状態遷移）。
- 「届く頃／時刻／色／封をする」は便箋の**下端から立ち上がる封筒のフラップ**として、書き終えてから開く（下から上へ ＝ `hierarchy-motion`）。
- 「封をする」後の演出を強化：現状の封蝋アニメに加え、**紙が折られ封筒に収まる**一連の動き（`transform` のみ、`prefers-reduced-motion` で静止）。

### 効果
「言葉を置く」までの摩擦と自意識が減り、**安心して書ける余白**が生まれる。
到着の物理演出は「これは投函され、時間をおいて自分に返る」という体験の核を、説明文なしで伝える。
