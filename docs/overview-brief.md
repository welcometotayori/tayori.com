## 1. プロダクトの基本情報とコンセプト

**「行き先を決めずにことばを放つ場所」**
自分の何気ない言葉が、誰かにとって救いの手になるかもしれない体験を提供するサービス。

- **コンセプト**: 匿名の80字を「宙（そら）」へ放つ。放たれたことばは宙に在り続け、
  だれかが偶然それを開くかもしれないし、だれにも読まれないまま漂い続けるかもしれない。
- **「空気の近さ」**: 色・季節・時刻・天気の4成分で、ことばとことばの隔たりを測る
  （色 42.1% ／ 季節 21.1% ／ 時刻 21.1% ／ 天気 15.7%。欠けた成分は外して残りで正規化）。
  **ただし、これが決めるのは「誰と出会うか」ではなく「どう見えるか」**——2026-07-27 に選抜から外し、
  いまは紙片の大きさ（近い＝大きい）と、探した時の並びにだけ効く。宙は全員が同じ一枚を見ている。
- **目的**: 承認や比較のプレッシャーがないまま、自分の内面を自由に安心して話せる場所を作ること。
- **反応の仕組み**: 返事はつかず、数も順位も出ない。気に入ったことばを自分の棚に残すことが、
  実質的な like にあたる（棚は本人にしか見えず、書き手には数も相手も伝わらない）。
  「いいな」（印）は 2026-07-27 に廃止し、経路も閉じた。
- **読み手の逃げ道**: 気に障ることばは「もう見ない」で自分の宙からだけ消せる。書き手には何も伝わらない。
  別々の人が同じ一筆を消したときだけ管理画面に静かに並び、下げるかどうかは人が読んで決める（自動では下げない）。
- **ケアの方針**: つらい内容でも宙へ出すことを妨げず、ケア判定を掲載可否のゲートにしない。
  検知時は本人にのみ静かに相談窓口を提示し、投稿はブロックしない。
  門番が止めるのは**他人に及ぶもの**（誹謗中傷・脅迫・連絡先・所在・学校名）だけ。

## 2. 設計の判断基準（4つの「つくらない」）

- **承認をつくらない**: いいね数、順位、ランキングを見せない。
- **比較をつくらない**: 他者と自分を比べる要素を排除する。
- **返事をつくらない**: 会話やSNS的な相互作用を持ち込まない。
- **義務をつくらない**: 毎日ログインさせる設計ではない。

### AIと運営の立ち位置

- **AIの役割**: AIは書き手にならない。生成・要約・添削・返事をしない。
  やるのは「近さを測る」ことと、「探す」で**近くないものを捨てる**ことだけ。裁かず、順位を付けず、広告に使わない。
- **外へ出る一箇所**: 「探す」の選別だけは外部のAI（Google Gemini）へ渡している（`TAYORI_SEARCH_AI`・**本番はON**）。
  送るのは**すでに宙で匿名公開されていることば**と著作権の切れた一節だけで、書き手を指すものは送らない。
  無償枠を使っているため向こうの学習に使われうることを、規約・ポリシー・/about に隠さず書いてある。
  旗を下ろせばその場で止まり、/about の文面も自動で「外へ出るところはありません」に変わる。
- **情報の透明性**: 実装と約束（規約等）を直結させる。見せないものは運用の心がけではなく、
  **経路を作らない**という構造で担保する（例：宙のことばのidは逆引きできないハッシュのまま）。
- **運営の閲覧**: 2026-08-03 に「覗き窓を閉じる」を撤回し、本文つきの分析を規約・ポリシーに明記した。
  ただし付箋・下書き・掲載の確認を通っていないことば・退会済みデータは、日常の閲覧対象から外してある
  （障害調査・法令対応を除く）。

## 3. 宙（キャンバス）の構造

全体は**一枚の無限キャンバス**。21室の部屋は壁ではなく、キャンバス上の**地形（島）**として在る
（出来事の部屋14＋気持ちの部屋7）。宙は誰でも見られる——門の向こうにあるのは「放つ」だけ。

### 地形と配置のルール

- **島の席＝同心円の輪**（2026-08-05）: 12時から時計回り、輪は内から 6・12・18 席、奇数の輪は半コマずらす。
  席順は部屋の生まれた順。輪の半径は「隣と重ならない」「内の輪と重ならない」の二つの下限から出す。
  ※ 意味の近さから座標を引く「意味の地図」（古典的MDS）はサーバ側に残っていて、部屋には `pos_x/pos_y` も入るが、
  **いまの遠景はそれを読んでいない**。地図の遠近より「あの部屋はあそこ」と体で覚えられる輪を採った。
- **ことばの配置＝帯（段）**: 島に降りたことばの束は段に組まれ、中心の段から順に埋まる。
  並びは「その部屋らしさ」——固有のことばほど中心、他の部屋にも掛かることばほど外側。
  段数は降りた時の眺めで決めて、寄っても変えない。
- **岸**: 島の縁のすこし外に、本から流れ着いた一節が島ごと32片。人のことばとは色も姿も違う。
- **沈降**: 古いことばほど深く（薄く・ぼけて）沈む（`1/(1+月数/12)`）。消えはしない。ときどき浮上する。

### UIと操作体験

- **視点**: 遠景（引く）では宙全体の地形——部屋の名と灯——が見え、近景（寄る）では島の中のことばが紙片として読める。
  遠景では紙片の字は出さない（居場所は足元の名が言う）。
- **頭の帯**: 名「たより TAYORI」（押すと全景へ帰る・2026-08-06） ｜ 検索の器 ｜ ＋書く ｜ しるし（戸＝メニュー）
- **足元の帯**: ＋−（寄り引き） ｜ 宙へもどる（島に降りている間だけ立つ） ｜ いまの面の名 ｜ 灯
- **操作体系**: 二本指スクロールやホイールは「ひきずる（パン）」、実機のピンチや修飾キー＋ホイールは「寄る・引く」。
  鍵盤では矢印＝ひきずり、＋−＝寄り引き、0＝全景、Escape＝島から宙へ。
- **重さ（カクツキ）対策の恒久ルール**:
  - 毎フレームのJS処理とブラウザの再描画を極力減らす（継承変数を根に書かない・しきい値に遊びを持たせる）。
  - 測ることと描くことを混ぜない。紙片の寸法はキャッシュし、画面の外に出るものは動かさない。
  - 操作中（手が触れている間）は灯の呼吸などの「急がない描画」を止める。

## 4. コア機能

### 4.1 放つ（書く）

ユーザーが新しいことばを生み出す唯一の行為。柱の中は「本文 → どこへ → いろ → かたち」の順で、
必須（本文・置き場所）と任意（色・題・向き）のあいだに罫が入る。

- **仕様**: 80字以内、匿名、部屋の指定が必須。放ってから **48時間**以内は取り消せる。
- **置き場所は書いた後に選ぶ**（2026-07-27）: 分類から逆算させると、書きたかったことが痩せるため。
- **気分の色**: 色相と濃さの二本の帯。既定色のまま触れなければ「選ばれていない」として扱い、
  空気の色成分から外す（表示の色味だけは残る）。
- **題（title）**: 10字以内・任意。漂っている間は出ず、棚と書架でだけ立つ。
- **書く向き**: 縦／横を選べる（入力のしやすさのため）。
- **打鍵の実時間再生（TypeTrace）**: 消した文字もためらいの間もそのまま記録され、宙で再生される。
  記録が始まるのは3文字目から——最初のためらいは残らない。

### 4.2 出会う（宙・探す・漂流物）

- **宙で出会う**: 選抜も抽選もない。生きていることばは全部その一枚に在り、**全員が同じ宙を見ている**
  （「もう見ない」を持つ人だけ、その人用の一枚が組まれる）。近さは大きさとして、時は深さとして見える。
- **探す（Semantic Gravity）**: 検索語をベクトル化し、コサイン類似度で近いことばを引く。
  下限（0.22／本の一節は0.35）を越えないものは混ぜずに落とす。AI選別がONのときは手前を 0.12 まで緩め、
  最大24片をAIに見せて「本当に関わりのあるもの」だけを選ばせる。
  **画面に出るのは人のことば9＋本の一節5**で、人が足りなければその空き枠を本が埋める（合計14は動かない）。
- **漂流物（外部テキスト）**: 青空文庫から抜いた一節が生成り色の紙として混ざる。
  手元のDBで **203,994片**（うち掲載中 197,520片）。部屋は一節ではなく**本まるごとの内容**から決める。
  探すが見ている板は10万片（fp32・約102MB）で、残りは島の岸でだけ出会える。

### 4.3 触れる・残す・届く

- **灯（ともしび）**: 直近30秒に自分以外のだれかがことばに触れていれば、7秒だけ灯がともる。
  島ごとの灯は「いまその部屋に誰かが居る」（75秒の窓）。**数えない・誰かは言わない**。
- **棚と付箋**: 出会ったことばを自分の棚に残せる。棚は10個まで、載せられることばは合計500まで。
  残す瞬間に自分だけの付箋（1件につき3つまで・24字）を貼れる——書き手には届かない。
  棚に入った控えは本文の写しなので、元が宙から降りても取り上げられない。
- **書架**: 自分が放ったことばを「年＋季節」で振り返る場所。
- **季節の返却**: 放ってから 3日〜365日 のどこかで、その時の日付・曜日・天気・気温・時刻を添えて
  書き手のもとへメールで帰る（同じことばにつき最大3回）。
- **降りてきました**: 放たれたことばは、乱数で選ばれた**もう一人**の宙へも降りる。
  書き手には届いたかも開かれたかも一切返らない。

## 5. インフラ・システム設計

「重い」と「動かない」を切り分けて手を入れてきた。

- **経路**: Render（Oregon）へ直接つなぐ。日本からの要求がCloudflare経由でSJCに引き込まれて
  遅くなっていたので、DNSはプロキシを外した（自前ゾーンはNRTを返す）。
- **器**: Render starter（512MB）／gunicorn 1 worker・8スレッド。SQLite は永続ディスク `/var/data` に置き、
  実行中はローカルのライブコピーを使って30秒ごとに書き戻す。
- **メモリ**: バックアップをストリーミング化（丸ごとメモリに載せて落ちた事故の後始末）。
  探すのベクトル板は fp32 のまま常駐させ、掛けるたびに開き直す代金を無くした
  （fp16 全量より、fp32 で10万片のほうが同じ常駐量で8倍速い）。
- **静的アセット**: canvas.css / canvas.js は中身のハッシュをURLに入れ、gzip 済みのバイト列を一度だけ作って
  `immutable` で配る。宙の一枚（JSON）も版ごとに一度だけ詰める。
- **バックアップ**: Cloudflare R2 へ日次、14世代まで。

## 6. 収益モデル（v1確定・実装済／戸は閉じたまま／2026-08-07）

課金対象を**「書く」から「集める」へ**移す。投稿数・投稿そのものは無料会員含め無制限。
有料化するのは**棚（コレクション）の容量**と、**探す・見せ方の質**。
サポーター枠は機能追加ではなく「気持ちの受け皿」——有料会員と機能は完全同一で、価格だけ上乗せする（Are.naのSupporterと同じ設計思想）。

**戸はまだ開いていない**（2026-08-07 Kosei）。新規ユーザーが **300人** を超えるまで、
契約の入口（Checkout／設定画面のプランの節）は閉じたままにする。仕組みは全部そろえてある。
限度（棚3つ・50件・80字）は**最初から効かせる**——先に緩めて後から締め直すと、
増えた棚を運営の都合で取り上げることになるため。

| 項目 | 無料会員 | 有料会員（Stripe） | サポーター |
| --- | --- | --- | --- |
| 料金 | ¥0 | **¥790/月 ／ ¥7,900/年** | **¥1,200/月 ／ ¥12,000/年** |
| 投稿数 | 無制限（スパム対策の軽いレート制限のみ） | 無制限 | 有料会員と同一 |
| 文字数上限 | 80字（罫4本） | 120字（罫6本） | 同一 |
| 棚の数 | 3つ | 10個 | 同一 |
| 棚の合計保存数 | 〜50件（トライアル上限） | 200件 | 同一 |
| 探す範囲 | 標準（人9＋本5） | 拡大（人18＋本10） | 同一 |
| 題（タイトル） | なし | あり | 同一 |
| グリッドカスタマイズ | なし（機能そのものが未実装・枠だけ） | あり | 同一 |
| 一括エクスポート | **あり（全プラン開放）** | あり | 同一 |
| ベータ先行アクセス | なし（枠だけ） | あり | 同一 |
| 追加投稿パック | 廃止（実装しない） | — | — |

年払いはどちらも「**10か月ぶん**」＝2か月ぶん安い。サポーターも月払い・年払いの両方を用意する
（Are.na の「年一括限定」は採らない／2026-08-07 確定）。

**実装（app.py）**:
- 差の在りかは `_PLAN_FEATURES` **一枚だけ**。各機能はここを引く（`_feat(plan, key)`）＝
  書き忘れた分岐で無料の人に有料機能が漏れる、を構造で防ぐ。画面へは `/api/me` と
  立ち上がり（`_boot_payload`）が写しを配る——**限度を画面側に書き写さない**。
- 字数：`api_create_letter` がプランで切る。書く柱の罫の本数（CSS `--ccol`）と
  打鍵を止める線（`MAX_COL`）は、同じ `poem_max` から出す。
- 題：無料会員には**引き金ごと出さない**（書く柱を「まだ買っていない」の一覧にしない）。
  送られてきても黙って落とす＝画面とサーバの二重に閉じてある。
- 探す範囲：広げるのは**出口の枠だけ**（`_search_slots`・`_SEARCH_WIDE_MULT=2.0`）。
  倍にしても AI へ差し出す件数は増えない＝プライバシー第4の2項「最大24件」は動かない。
- レート制限：無料会員のみ **1時間に5件**（`_FREE_POST_HOURLY_MAX`）。
- 戸：`_billing_open()`（`TAYORI_BILLING` = auto / on / off、`TAYORI_BILLING_MIN_USERS=300`）。
  画面を隠すだけでなく **Checkout API も 403** で断る。鍵（`STRIPE_SECRET_KEY`）が無い間は
  人数に関わらず閉じたまま。
- 値上げは Are.na 方式（事前に意見を聴く→理由を明文化して公表→**既存会員は据え置き**）。
  **規約第6条第9項に条文として書いた**。据え置きは Stripe 側で「古い Price を残す」ことで守る
  ——`_PLAN_PRICES` を書き換えても、契約中の Subscription が指す Price は変わらない。

**決着（2026-08-07）**:
- **一括エクスポートは全プラン開放**。`/api/export` は先に実装されていて、宙v1仕様書 §9 で
  「終了時期を決めない代わりの、唯一の保険」と位置づけて公開してある——あとから鍵をかけるのは
  書いた約束を取り下げること。Are.na も同じく全プラン開放している。有料へ寄せるなら
  `_PLAN_FEATURES["free"]["export"]` を False にするだけで閉じる。
- **サポーターも月払い・年払いの両方**（年一括限定にはしない）。

**未決定**:
- サポーターに機能以外の象徴的特典（ZINE・手紙などモノ・体験寄り）を1つ足すか。
- グリッドカスタマイズ／ベータ先行アクセスは、**フラグだけ在って中身が無い**。
  戸を開ける前に、どちらかは実体を持たせるか、表から落とすかを決めること。

**戸を開ける日にやること**（チェックリスト）:
1. Stripe ダッシュボードで Product / Price を4つ作り、`STRIPE_PRICE_*` を Render に入れる。
2. `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` を入れ、webhook の宛先を
   `https://…/api/billing/webhook` に設定（`checkout.session.completed` /
   `customer.subscription.updated` / `customer.subscription.deleted`）。
3. テストモードで、契約→ Portal で解約→ webhook で `plan` が戻ることを一度通す。
4. **/about の「80字まで」を書き換える**（有料会員は120字になるので、あの一行が嘘になる）。
   /privacy の投稿データの項は 2026-08-07 に先に直してある。
5. `TAYORI_BILLING` は auto のままでよい（300人で自動的に開く）。急ぐなら on。

  tayori を使っているか」の問い合わせ窓口になってはいけない。

### 残っているもの

**運用・耐久**

- 実行中のDBが `/tmp` のライブコピー（`_LOCAL_CACHE`）なので、落ち方によっては**直近30秒が消える**。
  `synchronous=OFF` も同じ割り切り。速さのために選んだ形（[[tayori-prod-latency]]）なので、
  戻すなら `TAYORI_DB_LOCAL_CACHE=0`、緩めるだけなら `TAYORI_PERSIST_SECONDS` を短くする。
  **人が増えるほど「30秒ぶんの誰かのことば」の重みが増す**ので、公開の前に一度は選び直すこと。
- R2 のバックアップ（日次・14世代）から**戻す手順が未検証**。取れていることと戻せることは別。
  一度だけ、落として戻す通し稽古をやること。
- パスワード再設定のメールが**実際に届くか**（Resend 経由）は、本番で一度確かめること。
  届かなければ、入れなくなった人の道はまだ開いていない。
